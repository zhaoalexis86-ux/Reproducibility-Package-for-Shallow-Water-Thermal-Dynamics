# CSITE data and code package

### 1. Package overview

This package accompanies:

**Seasonal Energy Budget and Thermal Stratification Stability in a Confined Shallow Thermal System: A High-Resolution Case Study**

The study uses 2024 meteorological observations and temperatures measured at five depths in an outdoor rectangular concrete basin in Wuhan, China, to examine air–water heat-flux partitioning, water-column heat storage, and thermal-stratification stability. 

This repository is a **workflow and code reproducibility package**, not a complete raw-data reproducibility package containing the full observational record.

### 3. Public/private data boundary

The public package contains the final code, aggregated figure data, daily/hourly/seasonal processed data, principal analysis results, the 100,000-row joint-parameter annual sample output, and short excerpts of real observations.

The complete 2024 10-min meteorological and five-depth water-temperature observations, and full-resolution intermediate files that could reconstruct those observations, are not publicly distributed. Consequently:

- external readers cannot regenerate every full-year figure and statistic from the original observations using the public package alone;
- public daily linkage and archived joint-sample results can be reproduced directly;
- authors with the private annual inputs can run the complete figure and analysis workflows;
- the meteorological, water-temperature, and stability-index files in `data/example/` are real 10-min excerpts covering 3 May 2024 00:00 through 5 May 2024 23:50; they demonstrate fields, data types, time formats, units, and code-reading conventions but cannot reproduce annual statistics.

`example_meteorology_water_temperature_10min.csv` contains the real three-day combined sample required by Figures 3 and 6. `example_figure4_temperature_profiles.csv` directly provides the measured five-depth temperatures at the five representative times used in Figure 4. `example_figure5_indices.csv` contains real Figure 5 indices for the same three-day period and retains missing values where no valid Rib estimate was available. All CSV files use UTF-8 with a byte-order mark so that Chinese headers display correctly in Excel.

### 5. Input fields and units

The time field is `Date` or `Time`, preferably formatted as `YYYY-MM-DD HH:MM:SS` or an equivalent string accepted by `pandas.to_datetime`. The original sampling interval is 10 min.

| Field | Meaning and unit | Main use |
|---|---|---|
| `Date`/`Time` | local timestamp | all figures |
| `25cm`, `75cm`, `125cm`, `175cm`, `225cm` | water temperature at the monitored depths, °C | Figures 3, 4 and 6; stability calculations |
| `风速(m/s)` | meteorological wind speed measured at 2 m, m s⁻¹ | Figures 2 and 6 |
| `大气温度(℃)` or a column containing `气温` | air temperature, °C | Figures 2 and 6 |
| `大气湿度(%RH)` or a column containing `湿度` | relative humidity, % | Figures 2 and 6 |
| `简易总辐射(W/m²)` or a non-cumulative radiation column | incoming shortwave radiation, W m⁻² | Figures 2 and 6 |
| `数字气压(hPa)` or a column containing `气压` | atmospheric pressure, hPa | Figure 6 |
| `St(J/m2)` | Schmidt stability of the monitored water column, J m⁻² | Figure 5 |
| `N2_max(1/s2)` | maximum squared buoyancy frequency, s⁻² | Figure 5 |
| `log10_Rib` | base-10 logarithm of valid Rib estimates | Figure 5; supplementary diagnostic |

Additional unused columns are permitted. Missing observations should remain blank or `NaN`; do not replace them with zero or forward fill unless the archived script explicitly does so. The scripts retain the final workflow's valid-record aggregation and explicit treatments. For example, Figure 6 clips negative shortwave radiation to zero, converts relative humidity from percent to fraction, and converts pressure from hPa to Pa. Rib is not a continuous full-year index, so invalid or weak-wind periods may be missing and are retained as gaps in Figure 5.

### 6. Python environment

Python 3.10 or newer is recommended. From the repository root:

```powershell
python -m venv .venv
.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
```

Principal dependencies are `pandas`, `numpy`, `matplotlib`, `scipy`, and `openpyxl`. EPS is written directly by Matplotlib. SVG-to-EMF conversion is optional and is attempted only if a user configures Inkscape; EMF is not required by this package.

### 7. Configuring local paths

All public scripts place local paths in the configuration block near the top. The repository root is normally detected by:

```python
REPOSITORY_ROOT = Path(__file__).resolve().parents[2]
```

Usually, no code edit is needed if private files are copied using the names in the table above. If files are stored elsewhere, edit only `INPUT_FILE` or `INPUT_INDICES`. Do not modify formulas, parameters, colours, axis ranges, or confirmed publication settings.

### 8. Recommended run order

From the repository root:

```powershell
python code/figures/Figure2.py
python code/figures/Figure3.py
python code/figures/Figure4.py
python code/figures/Figure5.py
python code/figures/Figure6.py
python code/figures/Figure7.py
```

Figure 7 must follow Figure 6; the other figure scripts are independent. Scripts can also be run from Jupyter with `%run code/figures/Figure2.py`. Newly generated files are written to `results/reproduced/FigureX/` and do not overwrite the archived final figures in `figures/`.

With the private annual inputs available, use this order for the additional analyses:

```powershell
python code/analysis/energy_budget_closure.py
python code/analysis/boundary_surface_sensitivity.py
python code/analysis/uncertainty_sensitivity_analysis.py
python code/analysis/robustness_joint_uncertainty.py
python code/analysis/revised_regime_classification_analysis.py
python code/analysis/predawn_robustness_analysis.py
```

The first two workflows depend on Figure 6; OAT depends on Figures 3 and 6; joint propagation depends on OAT; regime classification depends on the OAT MLD output and the private stability-index input. Missing prerequisites are reported with their expected paths.

The following public checks require no private annual data:

```powershell
python code/analysis/quantitative_linkage_public.py
python code/analysis/verify_joint_uncertainty.py
```

Outputs are written to `results/reproduced/quantitative_linkage/` and `results/reproduced/joint_uncertainty/`. Compare them with `results/expected/key_results.csv`.

### 9. Final-version status

- `figures/Figure2.*`–`Figure7.*`: confirmed final manuscript figures;
- `code/figures/Figure2.py`–`Figure7.py`: matching final plotting code, modified only for repository-relative paths;
- `data/processed/figures/`: final public figure/table data;
- CSV files under `results/`, except `reproduced/`: final reported analysis summaries;
- `results/expected/key_results.csv`: an index linking key manuscript values to scripts and outputs, not a new calculation.

Before public release, the authors should confirm the code/data license and update the release/version/DOI metadata in `CITATION.cff` after linking a tagged GitHub release to Zenodo.
